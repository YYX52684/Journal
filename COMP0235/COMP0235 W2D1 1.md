## lets do something useful

``` bash
vi playbook.yaml
```

```
- name: My first play
  hosts: mymachines
  tasks:
  - name: Ensure postgresql is at the latest version
    ansible.builtin.dnf:
      name: postgresql
      state: latest
  - name: Ensure postgresql-server
    ansible.builtin.dnf:
      name: postgresql-server
      state: latest
  - name: Ensure postgresql-contrib is at the latest version
    ansible.builtin.dnf:
      name: postgresql-contrib
      state: latest
  - name: Ensure postgresql-devel is at the latest version
    ansible.builtin.dnf:
      name: postgresql-devel
      state: latest
  - name: Ensure that postgresql is started
    ansible.builtin.service:
      name: postgresql
      state: started
~                       
```

``` bash
ansible-playbook -i inventory.yaml playbook.yaml --key-file ~/.ssh/ansible_key
```

OH NO, DIDN'T WORK, WE need to be root. We have to become:

```
- name: My first play
  hosts: mymachines
  become: true
  become_user: root
  tasks:
  - name: Ensure postgresql is at the latest version
    ansible.builtin.dnf:
      name: postgresql
      state: latest
~                       
```

What's happening here? The equivalent of `sudo dnf install postgresql postgresql-server` and then `systemctl enable postgresql` `systemctl start postgresql`


``` bash
ansible-playbook -i inventory.yaml playbook.yaml
```

log in to remote and lets find out...
``` bash
sudo systemctl start postgresql
journalctl -xeu postgresql.service
```
Ah! Take this info back to our control machine

edit playbook to add

``` yaml
  - name: initialise db
    shell: "/usr/bin/postgresql-setup --initdb"
```

